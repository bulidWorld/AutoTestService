# 接口自动化测试服务需求概述

## 1. 项目目标

采用 B/S 架构，用户通过浏览器管理项目、导入 YAML 接口定义、编排任务并执行 HTTP 请求，查看进度、参数和结果。支持固定参数，以及从前序请求响应中提取参数供后续请求使用。

需求分为三个阶段，每阶段形成可交付的闭环。后续阶段依赖前序阶段，但当前阶段的开发和验收不依赖后续功能。

## 2. 分阶段交付

| 阶段 | 目标 | 功能范围 | 验证方式 |
| --- | --- | --- | --- |
| [阶段一：项目与接口管理](phase-1/spec.md) | 建立可浏览、可复用的接口资产 | 项目管理、YAML 导入、全量更新、版本历史、接口详情 | 使用固定 YAML 样例验证解析、更新和失败回滚 |
| [阶段二：任务编排与基础执行](phase-2/spec.md) | 完成固定参数的测试闭环 | 任务管理、步骤顺序、固定全局参数、请求执行、运行历史 | 使用模拟 HTTP 服务验证顺序、参数和结果 |
| [阶段三：响应参数关联与运行可视化](phase-3/spec.md) | 完成接口数据关联和进度展示 | 响应提取、依赖校验、运行隔离、Pipeline 和步骤进度 | 使用模拟登录和业务接口验证参数传递、失败阻断及状态展示 |

验收使用可控样例和模拟服务，不依赖真实业务系统。每个阶段需提供验收数据、操作步骤及预期结果。

## 3. 核心数据模型

| 模型 | 所属关系 | 说明 |
| --- | --- | --- |
| 项目 | 顶层容器 | 管理 YAML 文件和任务，项目间数据隔离 |
| YAML 文件 | 属于项目 | 稳定的逻辑文件标识，关联多个版本和一个当前版本 |
| YAML 版本 | 属于 YAML 文件 | 保存原始内容、版本号、导入时间及接口集合，成功导入后不可修改 |
| 接口 | 属于 YAML 版本 | HTTP 方法、路径和参数定义；同一版本以方法加路径唯一标识 |
| 任务 | 属于项目 | 运行地址、全局参数定义及有序步骤 |
| 任务步骤 | 属于任务 | 引用明确的接口版本，保存参数绑定；同一接口可重复添加 |
| 全局参数定义 | 属于任务 | 阶段二为固定值；阶段三增加指定步骤的响应来源 |
| 任务运行 | 属于任务 | 一次执行的配置快照、状态、时间及独立参数上下文 |
| 请求记录 | 属于运行和步骤 | 实际请求、响应、耗时及失败原因 |

YAML 全量更新切换当前版本，保留历史版本。已有任务仍引用原接口版本，只有用户显式重新选择接口才应用新版本。

## 4. Pipeline 执行语义

1. **Pipeline 1：环境与参数准备。** 校验配置，创建运行快照，初始化固定参数；响应来源参数登记为待生成，不提前请求接口。
2. **Pipeline 2：请求执行。** 按步骤顺序解析参数，先创建请求记录，再发送 HTTP 请求并保存结果；阶段三在每步请求成功后提取响应参数、更新本次运行上下文，然后执行下一步。

每步骤每次运行最多发送一次请求，不自动重试。失败后停止后续步骤并标记为已跳过。不同运行的参数和记录相互隔离。

## 5. 本轮细化采用的范围约定

- 原说明未限定 YAML 格式，本轮以 **OpenAPI 3.0.x YAML** 为开发和验收基线。若已有自定义格式，应先调整阶段一格式约定和样例。
- 支持 HTTP/HTTPS、JSON 请求体和 JSON 响应提取；不包含文件上传、流式响应、脚本、循环、分支或并行步骤。
- HTTP 2xx 为基础执行成功；业务断言、自定义成功状态及报告导出不纳入本轮。
- 暂不包含账号、角色权限、定时任务、持续集成和跨项目参数共享。
- 技术栈、数据库和前端框架不由本需求限定。

## 6. 通用要求

- 列表有空状态，提交与运行有明确反馈；错误定位到文件、步骤或参数。
- 导入、更新及任务保存保证原子性，失败保留上一次有效数据。
- 数据持久化，服务重启后仍可查询；时间统一存储，页面按用户时区展示。
- 参数可标记为敏感，页面及应用日志默认脱敏；实际执行所需值妥善存储，原始内容或运行详情查看不得绕过脱敏。
