# 阶段三：响应参数关联与运行可视化

## 1. 目标与依赖

基于阶段二，将前序请求的响应值供后续步骤使用，并展示 Pipeline 和步骤进展。阶段二的固定参数任务继续可用。

## 2. 响应来源参数

- 参数来源增加“步骤响应”，配置名称、类型、是否允许为空、敏感标记、来源步骤 ID 和提取路径。每个名称只有一个来源定义。
- 从 JSON 响应体通过 RFC 6901 JSON Pointer 提取，例如 `/data/token`、`/items/0/id`；空路径表示整个 JSON。正确处理 `/` 和 `~` 的转义。
- 不支持响应头、Cookie、正则或脚本提取，不支持字符串模板拼接。
- 保存和运行前校验来源存在、规则合法及类型声明；消费步骤必须位于来源步骤之后，禁止引用当前或后续步骤参数。
- 排序或移除来源步骤后重新校验，指出受影响参数和消费步骤。
- 每次运行创建独立上下文：固定值立即可用，响应值初始待生成；不得复用之前运行的值。
- 来源请求成功后、下一步骤执行前提取并校验类型，成功才更新上下文。
- 非 JSON、路径缺失、类型不符均使当前步骤失败并阻断后续步骤，不用空值或旧值替代，不做隐式类型转换。
- `null` 仅在声明允许为空且消费字段允许为空时可用；object、array 保留结构。
- 同一步骤全部提取规则校验成功后一次性提交值，任意规则失败均不提交本步骤的提取值。
- HTTP 成功但提取失败时保留实际响应，单独说明提取错误。详情展示来源、生成状态及脱敏后的值。

## 3. 运行可视化

- 展示整体状态、起止时间、总耗时、已结束/总步骤数，分别统计成功、失败和跳过。
- Pipeline 1 展示环境校验和固定参数初始化；Pipeline 2 展示有序步骤及请求。
- 步骤展示状态、开始时间、耗时和摘要，突出当前执行步骤，保留未执行步骤位置。
- 响应来源步骤区分“请求执行”和“参数提取”子状态；失败展示停止原因及跳过步骤。
- 点击步骤查看请求、响应、提取结果和错误，敏感值脱敏。
- 运行期间自动更新，正常网络下状态变化在 3 秒内可见，可用轮询或推送；结束后停止持续刷新。
- 刷新恢复同一运行状态；断网提示状态可能滞后，恢复后重新同步，不重新启动任务。
- 历史运行保留最终 Pipeline、步骤和参数生成状态。

## 4. 标准验证流程

1. Pipeline 1 初始化固定 `username`、`password`，响应参数 `token` 为待生成。
2. 步骤 A 登录并保存响应，通过 `/data/token` 提取参数。
3. 步骤 B 的认证 header 整体引用 `token`，调用业务接口。
4. 步骤 C 查询结果，全部成功则运行成功。

若使用 Bearer 认证，模拟服务返回完整的 `Bearer ...` 字符串供整体引用。A 提取失败则 B、C 跳过，每步骤最多发送一次请求。

## 5. 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| P3-01 | 登录返回 Token，后续 header 引用 | 使用本次响应值，每步只请求一次 |
| P3-02 | 提取数组、嵌套对象和特殊字符字段 | 路径解析正确，类型保持 |
| P3-03 | 引用当前/后续步骤，删除或移动来源 | 校验失败并定位来源、参数、消费步骤 |
| P3-04 | 非 JSON、缺字段、类型不符 | 提取失败并阻断，原请求结果和原因可查询 |
| P3-05 | 同一步骤两条提取规则，一条失败 | 两条均不提交，步骤失败 |
| P3-06 | 连续运行返回不同 Token | 各自使用本次值，失败不复用旧值 |
| P3-07 | 两任务同时运行且参数同名 | 参数、进度和记录互不影响 |
| P3-08 | 延迟响应、页面刷新、断网恢复 | 正常网络 3 秒内更新，恢复后不重复执行 |
| P3-09 | 查看成功、请求失败、提取失败的历史 | Pipeline、步骤、请求和参数最终状态一致 |
| P3-10 | 运行阶段二固定参数任务 | 无需增加提取规则，原行为保持 |

模拟服务支持每次返回不同 Token、延迟、非 JSON 及缺字段响应。验收可重复验证关联、阻断、隔离和进度，不依赖真实业务服务。
