# 多任务组数据库与接口设计

本阶段已实现数据库 XML、OpenAPI YAML、业务管理、批次执行与运行查询；页面不在本次业务代码范围。
数据库唯一结构源为 `db/040_task_collections.xml`，契约为
`docs/ rest-api/rest-task-collection.yaml`。默认应用加载新契约。本次验证使用临时数据库 schema，业务数据库部署时再同步。

## 概念与范围

根据用户确认，移除原任务内步骤组功能，使用 `task_collections` 表示项目级多任务组。
任务组引用本项目现有任务，运行成员任务的全部步骤。
同一任务可属于多个任务组，同组不可重复，不支持嵌套。名称去除首尾空白后在项目内区分大小写唯一。
允许空组草稿；空组不可运行。更新使用 PUT 完整替换成员。

以下是需求未指定细节的设计约定：同序号并发、批次屏障、确定性合并、失败批次回滚写集，
以及组运行期间预约所有成员任务。成员 position 是 1～2147483647 的整数，允许重复和间断，
按数值升序执行；数组顺序不参与调度。

## 数据库

沿用 PostgreSQL、integer identity 主键、timestamptz、JSONB，无外键。
主键之外的名称唯一、合法状态、正整数、跨表归属由业务事务校验，与现有任务表一致。

| 表 | 主键 | 用途 |
| --- | --- | --- |
| task_collections | id | 项目级组名称、描述、时间 |
| task_collection_members | collection_id, task_id | 成员及可重复的批次序号 |
| task_collection_runs | id | 组运行状态、不可变完整快照、运行独立共享参数 |
| task_collection_run_members | collection_run_id, task_id | 成员状态、批次快照、独立 task_run_id |
| task_collection_parameter_overrides | id | 覆盖前后任务及任务运行来源，不存值 |

组运行快照包含组 ID/名称、成员任务 ID/名称/批次、任务完整配置、参数声明、接口版本及接口定义。
任务配置或接口资产后续变化不影响执行。`global_parameters` 初始为 `{}`，每项包含 value、
value_type、sensitive、source_task_id、source_run_id，仅成功批次可提交。
敏感原值仅用于执行，查询必须脱敏，禁止直接返回快照或共享参数 JSONB。

复用现有 task_runs、task_run_steps、task_run_parameters、task_requests 保存每个任务的执行细节。
通过 task_collection_run_members 判断组运行归属。新表定义和 API 不再提供旧步骤组的 group_id；
已有数据库中的旧可空列和旧表不自动 DROP。
组启动事务预建所有成员 task_runs（queued）、步骤及运行参数，成员状态为 pending。input_parameters 保存批次输入，ready 区分等待前序批次和可调度状态。
仅实际获得执行槽位后，成员与子运行进入 running；ready 与输入快照在同一事务冻结。
后续执行器必须通过成员关系识别这些子运行，禁止独立任务调度器抢占执行。
未执行的后续成员标记 skipped，其 task_runs 标记 failed，error_code=COLLECTION_MEMBER_SKIPPED，
未执行的步骤及参数标记 skipped；保留既有 task_runs 四种状态。
成员时间、耗时与错误从对应 task_runs 读取。

## 共享参数及覆盖

1. 新组运行创建全新上下文，不读取其他运行的结果。首批任务从空上下文开始。
2. 每批开始时冻结共享参数。同批成员各用独立副本，无法读取同批其他任务的新写入。
3. 任务先继承上批上下文，再初始化本任务 fixed 参数，按原有步骤顺序执行 REST 参数提取。
   同名 fixed 参数和成功提取值均为本地写入；只继承、读取参数不算写入。共享覆盖发生在成功批次合并时。
   所有任务声明的参数仍需合法；继承值可作为本任务已声明 REST 参数的初始可用值，
   无继承值的 REST 参数只能在其源步骤成功后使用。不引入未声明参数的自由引用。
   保存草稿允许已声明 REST 参数提前出现在绑定中，静态类型与源步骤仍校验；实际运行前必须证明输入可用。
4. 运行前静态校验所有成员：参数声明、表达式、类型及可用性。引用必须来自任务内已完成赋值，
   或严格较小批次的确定输出；不允许依赖同批任务输出。同名声明类型必须一致，否则 400。
   对动态访问整个 globalParam 的断言保守检查全部声明参数，沿用现有策略。
5. 一个任务的写集只保存它实际写入的参数最终值。同批全部成功后，协调者按 task_id 升序合并写集，
   因而同批同名参数由较大 task_id 最终覆盖；本任务参数名唯一，每个声明为 fixed 或 rest，运行内每个参数只写一次。
   较大批次覆盖较小批次。JSON null 也是已存在值，不能用真值判断覆盖。
6. 每一次覆盖都记录，即使值相等。失败批次未发布共享值，不产生共享覆盖审计。
   敏感标记只增不减，取原、新标记逻辑或；覆盖审计和日志均不输出原值及新值。
7. 覆盖不使运行失败。覆盖审计至少包含 collection_run_id、parameter_name、old_task_id、
   old_task_run_id、new_task_id、new_task_run_id、created_at。
   统一日志框架以 ERROR 输出 PARAMETER_OVERRIDDEN 和这些来源字段，保留请求 ID 等标准字段。
   批次合并覆盖与上下文更新同事务保存；协调者在后续独立事务读取待投递审计并输出日志。
   logged_at 保存投递时间，未投递项在重启后继续补发。
   审计分页支持日志轮转后追溯。日志输出失败不回滚已提交业务事务，持久化审计用于恢复补发，
   补发允许重复，按审计 ID 识别；不得声称日志文件与数据库能够原子提交。

例如 A(position=1) 写 token；B、C(position=2，B.id<C.id) 都读取 A 的 token，
各自完成后先合并 B 再合并 C，下一批读取 C 的 token。记录 A→B、B→C 两次 ERROR 覆盖。

## 调度与失败

批次内并发执行成员任务，仍受服务全局并发上限约束，达到上限时等待执行槽位；
任务内部步骤顺序不变。协调者等待本批所有已启动任务结束，全部成功才原子提交写集并进入下一批。
任何成员失败，本批成功成员的外部请求和运行结果保留，但整批写集不进入共享上下文；
尚未启动的本批成员及全部后续批次成员 skipped，组运行 failed。
失败任务的部分写入不传播，失败批次不新增共享覆盖审计，已提交成功批次的审计保留。
不自动重试，不自动回滚外部 HTTP 副作用。原有超时、断言及敏感信息脱敏规则继续适用。
重启恢复将遗留 queued/running 组及其全部未终止子运行标记 EXECUTION_INTERRUPTED，
未执行步骤/参数 skipped，不续跑、不传播未提交写集。终态成员结果不覆盖。

## 事务、互斥与清理

固定锁序为项目 → 任务组 → 按 ID 升序的任务；涉及多个任务组时按组 ID 升序。
所有相关写操作必须遵守同一锁序，避免相反锁序死锁。

- 组创建/更新事务校验名称唯一、所有成员存在且属于项目、任务不重复及 position 正数。
- 启动锁定项目、组及全部成员任务，校验所有快照后一次性创建组运行和子运行。任何错误整体回滚。
- 同组只能一个 queued/running；全部成员从接受时起至组终态均被预约。
  单任务运行及其他任务组运行必须检查活动组的成员关系；即使某个成员已提前结束，
  组终态前也不能独立再次启动。查询结合 task_collection_runs.status 和成员关系实现预约。
- 活动组禁止修改/删除配置，预约任务禁止修改/删除配置；锁住预约任务后检查活动组即可。
  业务实现扩展既有任务入口的互斥校验，不仅新增组启动入口。
- 删除任务：被任何活跃配置组引用时 409，先移除成员；已有历史引用不阻止删除。
  单独删除组仅删除配置及成员，不删除任务和运行历史；历史列表及详情按运行表校验项目归属，
  不依赖组配置存在。不存在配置且也无历史时 404，存在空配置时历史列表为空。
- 删除项目：有活动运行则 409，否则事务显式清理新组配置、覆盖审计、运行成员、组运行及既有任务历史。
  删除既有任务历史时，应连同对应组成员 task_run_id 处理，不能留下无法查询的子运行。
- 复制单个任务不复制项目级任务组；不新增复制任务组接口。

## 接口与后续实现

契约提供组列表/创建/详情/完整更新/删除、启动组运行、运行列表/详情、覆盖审计分页，共九个操作。
组运行 POST 无请求体。创建 201，启动 202，删除需 confirm=true 且返回 204；
输入或依赖错误 400、归属错误 404、名称/引用/活动运行冲突 409。
组运行详情返回成员 task_run_id，通过现有任务运行详情和请求查询接口查看各任务结果。
所有 ID 与既有接口一致使用正 int32；列表分页沿用 page/page_size。

业务测试覆盖：跨项目成员拒绝、重复成员拒绝、同批真正并发、跨批屏障、继承及同名覆盖、
同批确定性合并、ERROR 来源完整且无值、类型冲突、失败写集隔离、预约互斥、重启中断、
敏感标记传播以及删除组后历史可查。同时做 XML/XSD 与 OpenAPI 引用及规范校验。
